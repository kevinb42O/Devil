# Original audio: routing and clean playback

The original recordings now have a separate playback path. The replacement bank no longer supplies gain targets, role trims, or mastering to original sounds.

## Current implementation

- Every native cue has gain **1** and uses the byte-identical original WAV, including long recordings. No source is RMS-normalized, peak-normalized, or transcoded. The original `loudness.ini` is preserved unchanged as a sidecar and its numeric values remain in metadata. Its undocumented engine math is not guessed or treated as a linear gain formula.
- A single shared **0.25 output-headroom gain** applies to original effects, UI, and music before user volume. This is an explicit browser-output setting, not a recovered native balance setting. A shared safety compressor (-15 dB threshold, zero attack, 20:1 ratio) protects dense output at maximum user volume; it does not assign role-specific gains.
- Removed replacement-based gain derivation, role multipliers, ×3 chatter compensation, crowd/overlap normalization, combat-dependent effect-volume scaling, per-event gain trims, per-sound cooldown suppression, and synthetic room sends from original effects. Spatial voices use ordinary inverse-distance panning with unit rolloff and reference distance; they no longer use the old species-specific range profiles or extra distance fades.
- Voice selection still bounds concurrent processing. Native one-shots have a 48-voice budget with priority replacement; enemy loops have a 28-voice selection budget, crystal loops six, and homing drones eight. These are explicit browser resource limits, not per-source gain changes or claims about Sorath's allocation policy. Loading retry/backoff, stale-event cancellation, pause, and cleanup remain. Critical entrance/grab/countdown cues unlock and load independently of background bank warming, so long native WAVs cannot make a timely countdown expire behind unrelated decodes.
- Footsteps are the requested exception: all 24 dry/wet files, catalog values, ×5 gain, gait, wetness blending, near-field attenuation, and short room send remain intact. Their catalog is now isolated from the retired bank. Environment files, gains, chapter transitions, ascent, heaven, and environment-only combat ducking also remain intact as requested.
- Hands V/VI/VII retain the requested pairs **I+II**, **II+III**, and **III+IV**, including upgrades. Their composites use fixed 50/50 sample blending, preserving each input's recorded level. There is no replacement-bank target, per-hand normalization, or per-role trim. Extra-hand loop alignment and composite encoding are documented in the build script.
- Production packaging removes retired replacement effects and menu tracks. Only the preserved footsteps, original bank, composites, and requested environment recordings ship as active audio assets.

## Event coverage

The routing pass distinguishes normal jump, bunnyhop, precise/buffered hop, light/heavy landing, normal/homing weapons and impacts, native shotgun alternatives, ricochet families, pickups, enemy damage and crystal detachment, gushing towers, egg firing/hatching, feeding, attraction, burrowing, body contacts, and personal-best cues. New dagger milestones at 60/120/250/500/1000 seconds trigger their unlock cue once in eligible live solo runs; grabs always use the grab cue. Practice and replay playback do not award new unlocks.

The role cross-check uses the maintained [ddinfo audio catalog](https://github.com/NoahStolk/ddinfo-web/blob/master/src/DevilDaggersInfo.Web.Server/Utils/AssetInfo/AudioAudio.cs), a community reference rather than Sorath's engine source. The one-tick precise-hop classification is port timing, not a recovered native threshold.

Every imported recording has an explicit status in [the coverage ledger](artifacts/original-audio/coverage.json), generated by `npx tsx tools/audit-original-audio.ts`:

| Status | Count | Meaning |
| --- | ---: | --- |
| Routed | 203 | Connected to implemented events or requested composites |
| Extension input | 1 | `leveldown`, explicitly used by the requested extra-hand upgrade pairing and debug hand-I transition |
| Native unused/prototype | 34 | Reference marks these unused or prototype; includes uncertain unused classifications |
| Absent native behavior | 37 | Original debris bodies, title/branding sequences, lobby Easter eggs, friend-ranking warning, and Ghostpede floor-crash movement have no corresponding native event in this game |
| Unresolved | 0 | No imported recording is silently unaccounted for |

Unused prototypes are not randomly played. Liquid droplets are not substituted for bouncing meat or Orb shards, and the orbiting Ghostpede does not falsely announce floor crashes.

## Verification and reproduction

- `npm run assets:original-audio`: source/runtime hash verification, independent preparation and pair blending, then exhaustive coverage accounting. Native preparation uses Python standard libraries. Composite authoring uses NumPy and macOS `afconvert` for long extra-hand tracks.
- `npm run test:original-audio`: source integrity, byte-identical native copies, gain-policy isolation, footstep preservation, actual movement/contact events, source routing, rendered audibility, and Chromium/WebKit decoding/playback.
- `tests/audio-routing-browser.mjs` checks actual native source gains, absence of room sends, unchanged stream targets under different game states, actual impacts, reward triggers, retry/backoff, pause, and stale-voice cancellation. Numeric output is saved to `artifacts/original-audio/routing-audit.json`.
- `npm run build`: TypeScript, production packaging and offline asset generation.

## Native fidelity boundary

The old replacement-era processing is removed. This establishes clean playback of original recordings and explicit event coverage; it does **not** establish exact native-engine balance. The recordings and `loudness.ini` do not disclose the original HDR transfer function, native source gains, attenuation configuration, HRTF implementation, or voice allocation. Exact native balance requires original engine code or synchronized reference captures. Ordinary browser panning and one shared headroom stage are stated openly rather than presented as recovered Sorath behavior.

Shipping all native WAVs preserves their samples but increases the original bank from about 157 MB of encoded copies to about **503 MB**, before composites and the preserved environments. Files load on demand; long menu tracks stream, and the complete offline download explicitly includes the full bank.
